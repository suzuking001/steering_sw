# 検証記録と実機チェックリスト

## PC上で確認済み

- ESP32 DEVKIT向けPlatformIOビルド（espressif32 8.0.0 / Arduino 3.3.12）。
- ネイティブテスト53項目。AddressSanitizerとUndefinedBehaviorSanitizerを有効化。
  - Wi-Fi切断後の待機、30秒の接続試行、成功時の再試行停止、切断時の再接続、millis周回。
  - ログイン不要のローカルアクセス、更新時のCSRF、接続先IPとmDNSのHost検証。
  - 設定用BOOTの起動時押下無視、3秒判定、一度だけの発火、短押し、millis周回。
  - 公開設定JSONの往復、型不正・欠落・バージョン・NUL文字・マクロ参照の拒否。
  - 保存済みのADC・抵抗値モードと閾値を維持して旧設定を読み込めること。
  - 同一系統の範囲重複、未押下範囲、登録上限、非数値、抵抗値計算、ヒステリシス。
  - 起動時の押しっぱなし、ノイズ、短押し、ダブルクリック、長押し、音量連続操作。
  - 測定不能時の中止、未押下への復帰要求、判定リセット、millisの周回。
  - パスコードの10秒制限、ACCの一度だけのOFF検出。
  - 全印字可能ASCIIの変換、マクロの順序、切断・通知失敗時の中止。
  - OTAの版比較、対象アセット・サイズ・SHA-256・ダウンロード先の検証と、署名付きURLに必要な送信バッファーの確保。
- Chromiumのブラウザーテスト67項目。
  - パスワード入力なしの画面表示、ライブ表示、回路定数の変更・保存、範囲重複の拒否。
  - ボタン名の入力、重複しない名前の提案、両系統のライブ値、カードへ取り込んだ値の編集と保存、マクロ追加。
  - 学習結果の編集反映と、保存までは設定を変更しないこと。
  - 本体設定で両系統の未押下値を直接取り込み、古い測定値を拒否し、BLEを一時停止せずに保存できること。
  - 3つの押し方のテスト要求、未割り当て・未保存のマクロ変更の扱い、パスコード割当の「数字テスト」要求、秘密情報を含めないバックアップ。
  - 初期ショートカットと変更後のキーの組み合わせの表示。
  - 送信中だけ中止ボタンが表示され、押すと送信を停止すること。
  - Bluetoothの準備状態、名前と有効設定の保存、ペアリングを保持した再接続。
  - Wi-Fiと端末パスコードの入力保持、表示切り替え、保存失敗時の入力・未保存状態の維持。
  - 画面下の保存でパスコードをWi-Fiより先に保存すること、同じSSIDのパスワード省略時に登録値を維持。
  - 保存済みと接続成功の区別、接続失敗の継続表示、再接続要求、PC用URLとSSIDの表示。
  - 再表示で秘密情報を読み出さず登録済みプレースホルダーを示すこと。
  - JSON復元時の出力OFF・ネットワーク維持、不正JSONの拒否。
  - 幅390pxでの横はみ出しなし、未処理例外なし。
  - Cookieなしでの再接続、再起動後のトークン再取得、未入力トークンの更新拒否。
  - タッチ端末のフォーカスに連動するBluetoothの停止と復帰、入力欄間の移動、停止要求中にフォーカスを外した場合、ページを離れた場合。
  - 定期更新中の入力欄フォーカスと入力内容の維持。
  - ページ内キーボードで英数字・記号を入力できることと、パスコードの先頭のゼロが残ること。
  - トークンなしのOTA更新確認、公開リリースが取得できない場合の表示、実行・進捗・再起動後の版表示、未保存設定の保護。

ブラウザーテストのHTTP・テレメトリー・BLE状態はシミュレーターです。設定検証は実際のC++コーデックを呼び出しています。画面例は `.pio/ui-tests/desktop.png` と `.pio/ui-tests/mobile.png` に生成します。実際のESP32 HTTPサーバー、NVS、無線通信の検証を代替するものではありません。

再実行はREADMEの開発コマンドを使用してください。

## 実機で確認する項目（未実施）

### USB・単体

- [ ] ESP32 DEVKIT V1への書き込みと起動、115200bpsでの初期パスワード表示。
- [ ] 設定用Wi-Fi・既存LANのどちらからもWebパスワード入力なしで設定画面が開くこと。Wi-Fiパスワードは更新で変わらないこと。
- [ ] 起動後のBOOT長押しでAPが開き、ボタン・Wi-Fi・パスコード設定を消さないこと。
- [ ] 設定用Wi-Fi接続時に端末に設定画面が自動表示されること。表示しない場合もIPから開けること。
- [ ] USBの `SETUP` でSSIDとWi-Fiパスワードが再表示されること。
- [ ] 既存LANからの未知ページや `/api/` が設定用APへ転送されないこと。
- [ ] 設定用APへ接続し、`http://192.168.4.1/` で設定画面を直接開く。
- [ ] 電源再投入で公開設定・パスワード・BLEペアリングを復元。
- [ ] 自宅Wi-Fiの接続先が未登録・登録済み・圏外の各状態で、起動時から設定用APのSSIDが見えること。
- [ ] 既存Wi-Fiへの接続と復旧後、設定用APと既存LANの両方からページが開くこと。
- [ ] 実際のSSID・パスワードで「保存済み → 接続成功」となり、表示されたPC用URLから同じLANのPCでアクセスできること。
- [ ] 間違ったWi-Fiパスワード・存在しないSSIDで失敗表示が出て、修正して再接続できること。
- [ ] タッチ端末でWi-Fi・パスコードを入力し、専用保存と画面下の保存の両方で値が残ること。
- [ ] `steering-sw.local` とIP直指定でのアクセス。
- [ ] 大きな設定での空きRAM・保存動作、設定保存中の入力監視。
- [ ] 保存中の電源断から、有効な設定またはもう一方のスロットへ復旧すること。

### GitHubからのファームウェア更新

- [ ] 旧版からUSBで移行し、設定・パスコード・ペアリングを復元できること。
- [ ] 非公開リリースから新しい版を取得し、再起動後に設定を維持して動作すること。
- [ ] 取得中にWi-Fiを切断したときやSHA-256が一致しないとき、現在の版で運用を再開できること。
- [ ] 更新後の起動確認に失敗するテスト用の版で、前の版に戻ること。

### 車両のステアリング入力

- [ ] 年式・ハーネスに合った信号線とスイッチ共通線を確認。
- [ ] 純正機器から切り離した抵抗ラダーのみをESP32へ接続。
- [ ] GPIO36・39の電圧が範囲内、未押下と各ボタンの値が安定。
- [ ] 未押下、全ボタンを学習し、隣接する範囲が重複しないこと。
- [ ] 短押し・長押し・ダブルクリック、音量連続操作が意図どおり。
- [ ] 長押し後に短押しが重複せず、起動時に押しっぱなしでも発火しないこと。
- [ ] 同一系統の複数同時押しで別ボタンの抵抗値にならないか確認。抵抗ラダーの性質上、同時押しを区別できない組み合わせは割り当てで解決しない。
- [ ] 実車の電源変動・温度・ノイズに対して許容幅が適切。

### Bluetoothで操作する端末

- [ ] 端末の機種とOSバージョンを記録。
- [ ] BLEペアリング、再起動後の再接続、画面ロック中からの接続。
- [ ] 音量、再生／一時停止、前後の曲、ホーム、Cmd＋Tab。
- [ ] フルキーボードアクセスでGoogleマップ・YouTube・Siri・ロック・アプリ一覧の専用キーを登録。
- [ ] 各アプリの起動、再生中のメディア操作、Siri呼び出し。
- [ ] ロック解除済みの端末のメモに「数字テスト」で `0123456789` が入ること。
- [ ] パスコード入力画面で数字が1回だけ入り、画面解除できること。
- [ ] 起床Spaceと待機時間を調整し、再送が10秒制限されること。
- [ ] BLE切断中の操作が再接続後に再生されないこと。
- [ ] Webグラフ更新とBLE操作を同時に続け、キーが押されたまま残らないこと。
- [ ] タッチ端末で入力欄を選ぶとBLEが切断され、画面キーボードで入力できること。
- [ ] 入力欄から離れるとBLEが再接続し、古い操作を再送しないこと。
- [ ] 文字入力モード中のESP32再起動で通常モードへ戻ること。

### ACCを追加した場合のみ

- [ ] 車両の過渡電圧を考慮した保護回路を用意。
- [ ] GPIO34のOFF/ON電圧としきい値を確認。電源保持時間を実測。
- [ ] 初回起動時からOFFならロックしないこと。
- [ ] ON→OFFでロックを1回送信し、電源が落ちる前に手順が完了すること。
- [ ] OFF時にBLE未接続の場合、再接続後に遅れてロックしないこと。
