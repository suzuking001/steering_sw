# Steering Switch — ESP32 Bluetoothコントローラー

自動車の抵抗式ステアリングスイッチから、Bluetoothキーボードに対応した端末を操作するPlatformIOプロジェクトです。

車種ごとの抵抗値は固定していません。2系統×各16ボタン、電圧／ADC／推定抵抗値による判定、許容幅、回路定数、短押し／ダブルクリック／長押し、操作マクロを日本語Web画面から変更できます。旧コード・Excelは `stearing_sw/` に保存したままです。

## 接続はこの2つだけ

**普段の操作はBluetooth、設定を変えるときだけWi-Fiです。** 車載ルーターがなくても使えます。

1. 操作する端末の「設定 → Bluetooth」で **Steering Switch** を最初に一度登録します。
2. 設定するときは、ESP32の起動後に Wi-Fiで **SteeringSW-xxxxxx** を選び、自動で開く画面を使います。
3. 画面が開かなければ、ブラウザーで **http://192.168.4.1/** を開きます。

パスワードを使うのはWi-Fi接続時だけです。Web画面でのログインはありません。最初のUSB接続時に表示されるWi-Fiパスワードを一度控えてください。

操作の順番は **[かんたん接続ガイド](docs/connection.md)** にまとめています。家庭・車内LANのPCから開くときは、「本体設定 → Wi-Fi接続」に表示される **PC用URL** を使用してください。`192.168.4.1` は設定用Wi-Fiへ直接接続した場合のアドレスです。

## 初回の使い方

1. [配線例](docs/wiring.md)を確認し、最初はUSB給電で動作を確認します。旧資料のACC分圧回路はそのまま使いません。
2. PlatformIOでBuild → Uploadを実行します。既存ファームウェアからパーティション構成を変更する初回は、必要な設定を控えたうえで `pio run -t erase` で全フラッシュを消去してから書き込みます（旧デバイス上の設定も消去されます）。通常の更新ではeraseは不要です。CLIの場合：

   ```bash
   pio run
   pio run -t upload
   pio device monitor -b 115200
   ```

   この環境で `pio` がPATHにない場合は `/home/hisa/.platformio/penv/bin/pio` を使用できます。ファームウェアは `.pio/build/esp32dev/firmware.bin` です。Web資産も含まれるため、ファイルシステムの別途書き込みは不要です。

3. 115200bpsのシリアル表示から次の値を控えます。
   - `Password`：設定用Wi-Fiへ接続するためのパスワード。
   - `Wi-Fi`：設定用Wi-FiのSSID。`SETUP` コマンドで案内を再表示できます。
4. PC・スマートフォン・タブレットを `SteeringSW-xxxxxx` に接続します。自動で開く設定画面をそのまま使えます。自動表示されない場合は `http://192.168.4.1/` を開きます。Webのパスワード入力は不要です。
5. **キー送信は初期状態でOFFです。**「本体設定 → 入力のライブモニター」で配線と電圧の変化を確認します。
6. 「ボタン割当」で名前を付けてカードを追加します。カードの「学習」を開き、スイッチを押したまま反応した系統の「現在値を設定する」を押します。
7. 短押し・ダブルクリック・長押しの操作を割り当てます。未押下の中心値を設定するときは、スイッチをすべて離して「本体設定 → 入力の詳細設定」で対象系統の「現在値を設定する」を押します。最後に「保存・適用」を押します。
8. [対応端末のショートカット設定例](docs/keyboard.md)でBLEペアリングと専用キー割り当てを設定します。
9. 「本体設定」の「キー送信を有効にする」をONにして保存します。停車中に各操作を確認します。

> ハードウェアへの書き込み・実車接続・接続先の端末での操作確認は、この実装作業では行っていません。[検証チェックリスト](docs/verification.md)を使用してください。

## できること

- ADC生値・中央値・校正電圧・推定抵抗値・認識中のボタンを約200msごとに更新。本体設定に2系統の電圧グラフを表示。
- 入力2系統の名前、電圧／ADC／Ωの判定単位、実際のプルアップ抵抗値、供給電圧、未押下範囲、ヒステリシスを編集。
- 各系統最大16ボタンを追加・削除。ボタン名、中心値、許容幅、各押し方の操作を編集。
- カードの各操作欄にある「テスト」から、選んだ操作を接続先へ1回送信。キー送信を有効にしてBLEを接続しておきます。変更したマクロを試す場合は先に保存します。
- 初期割り当ては次の表。Googleマップなどの専用キーも「マクロ」から編集可能。
- 最大16マクロ・各32ステップ。通常キー、修飾キー、メディアキー、ASCII文字列、待ち時間に対応。合計30秒以内。
- 4〜12桁の数字パスコードを別途登録し、実ボタンの長押しで1回送信。接続時の自動送信、結果不明時の再試行、Webからのパスコードテストはありません。
- 設定用Wi-Fiは電源投入時に起動します。登録済みの2.4GHz Wi-Fiにも並行して接続します。
- 設定用Wi-Fiが見つからない場合は、起動後にBOOTボタンを3秒長押しして起動を再試行できます。設定用Wi-FiではDNSと接続確認用ページで設定画面へ案内。自動表示されなければIPでアクセス。
- IPアドレスまたは `http://steering-sw.local/` でアクセス。mDNSが利用できない端末ではIPを使用。
- Wi-Fiの「保存済み」「接続中」「接続成功／失敗」を分けて表示し、PC用URLを案内。入力したWi-Fiパスワード・端末パスコードは保存後も残し、表示切り替えで確認できます。再表示時は「登録済み」として示します。
- 画面下の「保存・適用」でも、変更した本体設定・端末パスコード・Wi-Fi設定を保存します。接続先を変えるWi-Fiは最後に保存します。
- 設定の再起動後復元、名前付き設定のJSONダウンロード／読み込み、初期化、再起動、BLEペアリング削除、操作ログ。
- タッチ端末で入力欄にフォーカスがある間はBluetoothを一時停止し、欄から離れると再接続します。
- 将来のACC OFF連動ロック。初期状態は無効。保護済み入力信号と電源保持が必要です。

## 初期割り当て

| ボタン | 短押し | ダブルクリック | 長押し |
|---|---|---|---|
| MUTE | 再生／一時停止 | — | — |
| ＋／－ | 音量変更 | — | 連続で音量変更 |
| MODE | ホーム | アプリ一覧 | Siri |
| ＞ | 次の曲 | — | Googleマップ |
| ＜ | 前の曲 | — | YouTube |
| 通話 | Cmd＋Tab | — | — |
| 電話ON | — | — | パスコード送信 |
| 電話OFF | ロック | — | — |

短押しは離した際に送信します。ダブルクリックを割り当てたボタンでは、単発の短押しは初期値300msの確定待ちがあります。長押しは初期値800msで1回だけ発火し、離した際の短押しを抑制します。音量は安定した押下を検出した直後、続いて450ms後から100ms間隔で送信します。音量短押しに別の長押し／ダブル操作は併用できません。

起動時、設定適用後、学習後、BLE接続・切断後は、安定した未押下状態に戻るまで入力を受け付けません。範囲外への変化は操作中止として扱い、別ボタンへ直接変化しても未押下に戻るまで新しい操作を開始しません。

## Wi-Fiパスワードと復旧

Web画面のログインは廃止しました。設定用Wi-Fi、または同じ家庭・車内LANへ接続した端末から、そのまま設定を編集できます。Wi-Fiへ接続するためのパスワードは維持します。

Wi-Fiパスワードと端末パスコードは設定JSONに含めません。暗号化されていないNVSへ保存し、Webから内容を読み出す機能はありません。以前保存されたWeb管理パスワードは使用しません。

USBシリアルから `SETUP` と改行を送ると、設定用APを起動してSSID・Wi-Fiパスワード・URLを再表示します。`HELP` でコマンドを確認できます。以前の `EASY_SETUP` / `RESET_ADMIN` は接続案内の表示として受け付け、パスワードを変更しません。

「入力・Wi-Fi・パスコードを初期化」は設定用APのパスワードとBLEペアリングを維持します。BLE情報は専用ボタンで削除し、接続先の端末でも登録解除します。

設定用には通常のNVSと分けた128KBの `settings` パーティションを確保します。設定はNVSの2スロットへ交互に書き込み、読み戻して確認した後に有効スロットを切り替えます。起動時は選択スロットが不正ならもう片方を確認します。大きな設定は24KBまでです。失敗時は実行中の設定を維持します。

## 開発と検証

```bash
pio run
scripts/test_native.sh
node --check web/app.js
node scripts/test_web.mjs
```

ネイティブテストにはC++17コンパイラー、ブラウザーテストにはNode.js 22以降とChromiumが必要です。先に `pio run` で依存ライブラリを取得してください。テストは `.pio/` 以下に生成し、通常のファームウェアビルドには含まれません。ブラウザーテストはHTTPとBLE状態のシミュレーターを使用し、JSON検証には実際のC++実装を使用します。

- `src/config_codec.cpp` / `include/model.h`：設定形式、検証、入力分類、押し方判定。
- `src/runtime.cpp`：5ms周期の入力タスク、学習、ログ、ACC、操作の実行条件。
- `src/hid.cpp` / `src/macro_runner.cpp`：BLE HIDと待機で処理を止めないマクロ実行。
- `src/main.cpp`：認証、Web API、Wi-Fi、復旧コマンド。
- `web/`：端末内で動く画面。ビルド時にgzipでファームウェアへ組み込み。
- [APIと設定仕様](docs/api.md)、[配線](docs/wiring.md)、[端末設定例](docs/keyboard.md)、[検証記録](docs/verification.md)。

旧スケッチからはBLE接続時のパスコード自動入力、入力待ちで停止するwhileループ、固定パスコードを引き継いでいません。旧閾値は参考プリセットとして引き継ぎ、実車で校正する方式です。
